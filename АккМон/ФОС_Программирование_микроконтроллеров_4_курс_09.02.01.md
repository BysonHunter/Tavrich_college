# 1. Паспорт фонда оценочных средств

Фонд оценочных средств предназначен для контроля и оценки
образовательных результатов обучающихся 4 курса по дисциплине МДК.02.02
Программирование микроконтроллеров в составе профессионального модуля
ПМ.02 Проектирование управляющих программ компьютерных систем и
комплексов.

Оценочные материалы ориентированы на проверку теоретических знаний и
практических умений разработки, интеграции, тестирования, установки и
обновления управляющих программ для современных микроконтроллерных
систем на базе Arduino-совместимых плат, STM32/ARM Cortex-M, ESP32, RTOS
и промышленных интерфейсов связи.

## Практическое задание (профессиональные задачи)

**Задание 1. Обработка внешнего прерывания и антидребезг кнопки**

Разработайте алгоритм и фрагмент программы для микроконтроллера
STM32/Arduino-совместимой платы: кнопка подключена к входу с
прерыванием, светодиод - к цифровому выходу. При нажатии кнопки
состояние светодиода должно переключаться, ложные срабатывания от
дребезга должны подавляться программно. Предусмотрите вывод
диагностического сообщения через UART.

Ожидаемый результат выполнения: Корректное решение содержит настройку
GPIO входа с подтяжкой, GPIO выхода, внешнего прерывания/обработчика
события, переменной времени последнего события, проверку интервала
антидребезга 30-50 мс, переключение состояния светодиода и
диагностический вывод через UART/Serial.

**Задание 2. Управление ШИМ по данным АЦП с использованием
DMA/фильтрации**

Разработайте структуру программы, в которой значение с потенциометра
считывается через АЦП, фильтруется скользящим средним и преобразуется в
коэффициент заполнения ШИМ для управления яркостью светодиода или
скоростью двигателя. Укажите назначение ADC, DMA, TIM/PWM и переменных
программы.

Ожидаемый результат выполнения: Эталон: ADC считывает напряжение, DMA
переносит выборки в буфер без постоянного участия CPU, программа
вычисляет среднее значение, масштабирует диапазон АЦП в диапазон CCR
таймера, TIM формирует PWM. Предусмотрена периодическая диагностика и
ограничение диапазона.

**Задание 3. Обмен по UART/RS-485 с контролем целостности пакета**

Предложите формат пакета и алгоритм обмена между двумя
микроконтроллерами по UART/RS-485. Пакет должен содержать адрес
устройства, код команды, длину данных, данные и контрольную сумму.
Опишите действия передатчика и приемника при ошибке CRC.

Ожидаемый результат выполнения: Эталонный формат: START, ADDRESS,
COMMAND, LENGTH, DATA, CRC. Передатчик формирует пакет и считает
CRC/контрольную сумму. Приемник проверяет стартовый байт, адрес, длину,
CRC, выполняет команду только при корректной проверке. При ошибке пакет
отбрасывается, формируется NACK/сообщение об ошибке и запись в лог.

**Задание 4. Многозадачная система сбора данных на FreeRTOS**

Разработайте структуру программы FreeRTOS для устройства, которое
считывает температуру, напряжение питания и состояние дискретного входа,
выводит данные на дисплей и передает их по UART/MQTT. Опишите задачи,
очереди/семафоры и приоритеты.

Ожидаемый результат выполнения: Эталон: TaskSensor периодически
считывает датчики, TaskDisplay обновляет экран, TaskComm передает
данные, TaskDiag контролирует ошибки. Данные передаются через queue,
доступ к общему буферу защищается mutex, временные интервалы задаются
vTaskDelay(), критические события могут сигнализироваться semaphore.

**Задание 5. Обновление прошивки и диагностика микроконтроллерного
устройства**

Предложите план обновления версии управляющей программы
микроконтроллерного устройства с учетом bootloader, совместимости
аппаратной версии, проверки целостности прошивки и восстановления после
неудачного обновления. Опишите диагностические проверки после
обновления.

Ожидаемый результат выполнения: Эталон: проверяется версия платы и
прошивки, резервируется старая версия или предусмотрен безопасный режим,
новая прошивка передается bootloader, проверяется CRC/подпись,
выполняется перезапуск, затем тестируются GPIO, ADC, UART/I2C/SPI,
память, watchdog и основные функции. При ошибке выполняется откат или
переход в режим восстановления.
